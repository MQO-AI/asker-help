Publish a standard report snapshot to give stakeholders a prepared, read-only view of its results.

{/* Available with */}
{/* Let Q-bit do it */}

Report authors should review the report, filters, bases, and privacy settings before creating a link. For example, check a regional comparison and its public bases before sharing the prepared report with the project team. A saved report definition does not refresh an existing shared snapshot.

1. In the report workspace, set **Minimum public base**. The default is 5 and the permitted range is 5 to 100. Public cells below the minimum and rare written phrases are withheld. Experiment results follow the same minimum-base rules.
2. Decide whether to enable **Allow chart exports in shared reports**. It starts off. For a word cloud, separately decide whether to **Include these words in the published report**.
3. Choose **Share** to open **Publish and share**, then choose **Update shared report**. Unsaved changes are saved before preparation. Wait for the update to finish.
4. Under **New share link**, enter a label and optionally set a password and expiry. Create the link and share it with the intended recipients. Check the prepared report and its generated time.
5. Use the link controls to edit or revoke access when needed.

A shared link shows the last successfully prepared snapshot. New responses or saved edits do not automatically replace it. Choose **Update shared report** again when you want the shared results refreshed. While an update is queued, or if it fails, the previous successful snapshot remains visible. Retry when preparation is available and check the generated time.

A password and expiry limit access to the link. Revoking it prevents future access through that link, but cannot recall material a recipient has already saved.
