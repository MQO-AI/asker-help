Q-bit coding groups selected written answers into themes for review and analysis.

{/* Available with */}
{/* Let Q-bit do it */}

Analysts can request coding when preparing survey data. For example, code a question asking how a community service could improve, then read the theme definitions and individual assignments before reporting a result. Written answers may contain identifying details, so include only the questions needed for the analysis.

1. In **Inputs**, open **Data**, choose survey responses, and opt in to written answers.
2. Under **Questions to code**, select the eligible questions. None are selected by default. Prepare the data version.
3. When preparing a later version, choose **Fresh codebook and full recode** or a prior codebook where offered. Fresh coding can reveal new themes. Reuse carries validated assignments forward for matching unchanged text and codes new or changed text against the existing themes.
4. Review the generation sample, theme definitions, prevalence, and any refinement before using the results. Open **Open-ended codebooks and coding** to inspect coded answers. The table shows the first 100 rows; downloads include all rows.
5. Use **Download codebooks and all coding** for JSON, or **Download response coding (CSV)** for an individual question.

For a question with at least 75 nonblank answers, the current coding path uses Content Coder. Reusing a prior codebook also uses Content Coder, even when fewer than 75 answers remain. Both require Content Coder access and available usage capacity. A smaller set without a reused codebook uses direct assessment. Check the sample base separately from the full coding base. Responses may receive multiple codes, so theme percentages can total more than 100%.

To send a separate copy to a colleague for work in Hub, use [Send open ends to Content Coder](./send-to-content-coder).
