Review Q-bit proposals to decide which requested changes should be applied to a survey draft.

{/* Let Q-bit do it */}

## When to use it

Use a programming conversation linked to an existing survey when you want help revising its saved setup. For example, request a new follow-up question and review both its wording and its relationship to earlier questions before accepting it. Save your current builder edits before requesting a change so the proposal uses the current saved draft.

When using the assistant on a screen, open **Context details** to check whether visible unsaved details are also included in the request. Those details are not saved by asking Q-bit. See [Use Q-bit on the current screen](../get-started/use-q-bit-on-the-current-screen).

1. In Survey Builder, select **Q-bit** to open the survey's assistant. Add source files through **Inputs** if they are needed for the request. Describe the change in **Message Q-bit** and select **Send**.
2. When the proposal is ready, select **Review Survey draft changes**. Expand **Compare before and after** for each change and select the changes you want to decide on.
3. If a selection cannot be saved, review the validation messages. Include the related changes or ask Q-bit to revise its proposal.
4. To apply selected changes, hold editing access in Survey Builder and save your current edits. Select **Accept selected to Draft**. To reject selected items, choose **Decline selected**.
5. Review the updated draft in the builder, save any additional edits, and test the affected paths. Publishing remains a separate action.

You can decline a proposal even when you cannot apply it. If a decision is interrupted, use **Retry this decision** to recover the same result. If your editing access has changed, return to the builder and resolve access or draft conflicts before applying.

## Reply to review comments

In Survey Builder, review the Q-bit comments and choose **Save reply** for each response you want to send. Save the survey draft, then choose **Ask Q-bit to update draft** to send the saved replies together. Saving replies alone does not send a request or apply a proposed change. Review the resulting proposal and use **Accept selected to Draft** for changes you approve. Publishing remains separate. Comments are available to staff with survey access.
