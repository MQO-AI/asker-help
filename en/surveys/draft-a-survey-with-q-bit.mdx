Use Q-bit programming to turn instructions and optional source material into a survey draft that you can review and test.

## When to use it

Use this workflow when you have a questionnaire, brief, or clear description that can provide a starting point. For example, supply a community survey brief and describe the intended audience, question order, and any known routing. If you want to change an existing saved survey instead, use the [review workflow](./review-q-bit-survey-changes). Review the resulting survey before publishing it.

## Prepare a draft

1. From **Surveys**, select **Text to Programming**, or begin from the relevant project. From the central Q-bit page, you can also choose **Create a setup**. Under **What are you creating?**, select **Survey**, choose the project, and select **Start programming conversation**.
2. Optionally, open **Inputs** and use **Add source file** for a questionnaire, brief, or other material. Supported files include Word, PowerPoint, PDF, Excel, CSV, and text. You can add up to six files of 8 MB each.
3. To use another Survey as a reference, open **Reference another survey** in **Inputs**. Search by name or paste an accessible builder or respondent link. Select up to three references. They use the latest saved drafts without per-link settings; proposed edits stay in the current setup.
4. Describe the survey, audience, requirements, and decisions Q-bit should follow in a message, then select **Send**.
5. Review extraction warnings, **Source coverage**, assumptions, questions for review, and any work still to programme. If you supplied files, compare the draft with them, including material that may not extract cleanly. Q-bit uses extracted text.
6. Select **Open survey draft** when it is ready. Review wording, choices, logic, comments, and provisional decisions in Survey Builder. Save and [test the survey](./preview-and-test) before publishing.

Q-bit creates a working draft. Review and publication are separate steps. Do not assume the source has been fully implemented until you have checked it.

## If a build is interrupted

Open the saved progress and review the last validated section. If **Resume build** is offered, use it to resume the saved build. If an upload or request was interrupted, use its retry control rather than starting a duplicate. Keep sensitive source material within the permissions appropriate to your project.
